## Findings by severity

**Critical**
- **Filter/taxonomy row is present in markup but invisible on-screen, on all 5 routes.** The copy dump for every single tag page includes a full filter chip set (`All`, `Candidate Experience`, `Technical Hiring`, `AI & Assessment`, `Hiring Philosophy`, `Hiring Strategy`, `talent-acquisition`, `decision-infrastructure`) sitting right after the subhead — but none of it appears in any desktop or mobile screenshot. Instead there's a large dead whitespace band between the hero subhead and the card grid. This is either a CSS visibility/contrast bug (e.g., white-on-white chips) or a component failing to mount, and it repeats identically across every route reviewed — a systemic defect, not a one-off. It also means users landing on a tag page have no visible way to browse to other tags, which defeats the purpose of a tag/taxonomy page.

**High**
- **`/tag/time-to-hire/` content mismatch (owner-check item, not a design blocker):** the single article shown has no visible "time-to-hire" tag/category — it's labelled Technical Hiring / Signal Based Hiring. Verify this is intentional data (e.g., an internal tag not rendered as a pill) vs. a taxonomy bug before treating the page as correct.

**Medium**
- **Disproportionate whitespace makes near-empty pages look broken.** Every one of these tag pages has only 1–2 posts. Combined with the missing filter row, the hero-to-content gap reads as an unfinished/broken page rather than a sparse index — this will get worse, not better, as more tags exist with zero or one post.

**Low / none observed**

Header, hamburger nav, and footer are all consistent with the homepage baseline (Fraunces headings, mono red eyebrow/section labels, red accent pills, dark footer with correct link columns).
