## Findings by severity

**Blocker (functional/content bugs)**
1. **Broken tag filtering / duplicate content:** `/tag/platform-design/`, `/tag/privacy-by-design/`, and `/tag/professional-respect/` all render the exact same single post, and only one of the three tag labels ("Privacy By Design") actually matches it. This looks like the tag→post query is falling back to an unfiltered/incorrect result set for at least two of the three slugs. Needs an engineering fix, not a copy fix.
2. **Invisible/dead filter control:** All five routes' copy dumps list a full row of category filter pills (All, Candidate Experience, Technical Hiring, AI & Assessment, Hiring Philosophy, Hiring Strategy, talent-acquisition, decision-infrastructure) that never appear in any screenshot at 1520px or 390px. Either the markup is present but styled invisible (e.g., white-on-white, zero height, or off-canvas), or it's rendering behind/above the hero and getting clipped. This is a dead-looking control at best and a rendering bug at worst — worth a DOM/CSS check.

**Major (content/trust)**
3. **Unsourced statistic-style claim:** job-search-tips post cites "research from McKinsey, Deloitte, and PwC" with no visible link, footnote, or attribution in the rendered card/excerpt. Flag for owner: confirm this citation is substantiated (linked source or footnote) elsewhere in the full article; as shown on the tag-listing page it reads as an unverified name-drop.
4. **Raw-slug headings:** All five pages use the literal URL slug as the H1 ("human-first-hiring", "job-search-tips", "platform-design", "privacy-by-design", "professional-respect") rather than a formatted, editorial title (e.g., "Human-First Hiring"). This breaks the Fraunces-editorial voice used elsewhere on the site (compare to the polished, sentence-case headlines in the home baseline) and reads as unfinished/placeholder copy.

**Minor**
5. **Generic, non-differentiated subhead:** every tag page shares the identical description "Notes on hiring, assessment and the candidate experience." — no tag-specific framing, so five different tag pages feel like one templated page with a different word swapped in the title. Low cost to make each subhead reflect its actual tag topic.
6. Single-post pages: each tag currently has exactly one matching article, so the page reads sparse (a lot of empty white space below on desktop 1520, particularly on the home page cushion). Not broken, but worth flagging to the owner as content-coverage thin — more posts per tag, or a "no more posts yet" treatment, would look more intentional than a mostly-blank page.

## What's working well
- Header, hero band, warm-paper article-card section, and dark footer are all pixel-consistent with the home baseline across all five routes and both breakpoints — no layout regressions, no overflow, no broken images.
- Mobile (390px) reflow is clean: image stacks above metadata, tag pills wrap properly, footer columns stack in a readable order.
- CTA/nav bar (mono "Coverage / Services / Intelligence" etc., red "Start with one role" button) renders correctly and consistently — no dead-looking primary CTAs found on these five routes.
